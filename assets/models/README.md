# assets/models (Dev A)

The 3D masterplan of the **fictional** Azure Crest Residences: a waterfront pair of white towers with
wavy balcony slabs, bronze fins, glass sky-lounges and rooftop pools. The style takes inspiration from
references, but the design is original. Do not model real projects.

The model is **generated by code**, not hand-modelled, so anyone can rebuild it with no Blender skills
and it always matches the seed data.

| Path | What |
| --- | --- |
| `source/build_tower.py` | Blender script that builds the scene from `assets/seed/project.json` and exports the GLB |
| `apps/web/public/models/azure-crest.glb` | Output the website loads (~550 KB, ~100 KB gzipped, no Draco/meshopt decoder needed) |
| `previews/` (git-ignored) | Optional Cycles renders for review |

## Rebuild

Blender 4.2 LTS (`winget install BlenderFoundation.Blender.LTS.4.2`), then from the repo root:

```powershell
& "C:\Program Files\Blender Foundation\Blender 4.2\blender.exe" -b --factory-startup -P assets/models/source/build_tower.py -- --seed assets/seed/project.json --out apps/web/public/models/azure-crest.glb --preview assets/models/previews
```

Drop `--preview ...` to skip rendering. Takes about 5 seconds to export and ~10 s per preview on an RTX 3050.

## Contract with `packages/3d`

- Every unit is its own mesh named `Unit.meshId` (`<building>_F<floor>_U<pos>`, e.g. `T1_F12_U02`).
  The script asserts all 152 exist. The website matches meshes to seed units by that name for picking and tinting.
- Coordinates: 1 unit = 1 floor; podium 0–2; towers at x = ±8; unit quadrants at ±1.9; the sea faces −z
  (positions 01/02 are the sea side). `packages/3d/src/layout.ts` holds the same numbers. Change both together.
- Plain PBR materials, no textures. Static parts are merged per material (~23 meshes), plus 152 unit meshes.
- If the GLB is missing or fails to load, `TowerScene` falls back to procedural boxes from the same layout.
