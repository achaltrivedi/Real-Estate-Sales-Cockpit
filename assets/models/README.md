# assets/models (Dev A)

The 3D masterplan of the **fictional** Azure Crest Residences: a waterfront pair of white towers with
wavy balcony slabs, bronze fins, glass sky-lounges and rooftop pools. The style takes inspiration from
references, but the design is original. Do not model real projects.

The model is **generated by code**, not hand-modelled, so anyone can rebuild it with no Blender skills
and it always matches the seed data.

| Path | What |
| --- | --- |
| `source/build_tower.py` | Blender script that builds the scene from `assets/seed/project.json` and exports the GLB |
| `source/cinematic.py` | Renders the layered hero stills in `apps/web/public/cinematic/` (Cycles, uses the 2048 px textures) |
| `source/tours.py` | Builds every residence interior and the amenities, renders the 360° tour panoramas into `apps/web/public/tours/` |
| `source/tours.json` | Floor plans + tour stops exported from the website (`pnpm --filter @gsc/web tours:export`), read by `tours.py` |
| `env/` (git-ignored) | Cached HDR window views (`<residence>.exr`, `sky.exr`, `ground.exr`) rendered from the exterior scene |
| `textures/*.jpg`, `textures/web/*.jpg` | Seamless travertine, plaster, oak, bronze and teak (2048 px for renders, 512 px baked into the GLB) |
| `apps/web/public/models/azure-crest.glb` | Output the website loads (~2 MB, no Draco/meshopt decoder needed) |
| `previews/` (git-ignored) | Optional Cycles renders for review |

Each tower is a rounded curtain wall: every home's glazing (`<unit meshId>`, the pickable mesh) follows the
curved glass line, with bronze mullions every bay, a transom at each floor line, the core and party walls behind,
and simple furniture, sheers and (in the same homes `isLit()` lights on the website) warm ceiling lights, so the
glass shows real rooms in the live model and in every render.

The GLB holds the whole waterfront: towers and podium, beaches with groynes, the promenade with lamps,
the marina with pontoons and yachts, two palm islands, parks and street trees, and a hazy downtown skyline
on the horizon (no nearby blocks, so the towers stand clear).
The sky and the reflective, animated lagoon are drawn live in `packages/3d/src/Waterfront.tsx`
(water surface at three.js y = -0.4; the beaches and pontoons are modelled around it).

## Images (`assets/images/`)

Raw photography goes in `assets/source-images/` (git-ignored, ~400 MB). Then:

```powershell
python assets/images/prepare_images.py   # removes the generator watermark, writes WebP interiors/amenities, textures, monogram, favicons
python assets/images/water_normals.py    # tiling water normal map for the live lagoon
python assets/images/city_facade.py     # window-grid texture for the distant skyline blocks (generated, no photos)
```

`prepare_images.py` needs `numpy` and `opencv-python`. It writes `apps/web/public/images/{interiors,amenities}/*-{800,1600}.webp`,
`assets/models/textures/`, `apps/web/public/brand/monogram.png` and `apps/web/src/app/{icon,apple-icon}.png`.
Rebuild the GLB afterwards if textures changed.

## Rebuild

Blender 4.2 LTS (`winget install BlenderFoundation.Blender.LTS.4.2`), then from the repo root:

```powershell
& "C:\Program Files\Blender Foundation\Blender 4.2\blender.exe" -b --factory-startup -P assets/models/source/build_tower.py -- --seed assets/seed/project.json --out apps/web/public/models/azure-crest.glb --preview assets/models/previews
```

Drop `--preview ...` to skip rendering. Takes about 5 seconds to export and ~10 s per preview on an RTX 3050.

## 360° tours

The tours are rendered, not modelled by hand: `tours.py` builds each residence from the same floor plan the
website draws (walls, doors, glazing, joinery and furniture from `apps/web/src/features/residence/floorplans.ts`),
furnishes and lights it, and renders an equirectangular panorama at every stop in `tour.ts`. The view through the
glass is a real HDR panorama of the exterior scene taken at that residence's floor (its tower hidden), so the sea,
the second tower, the beaches and the skyline sit where they are in the 3D model.

```powershell
corepack pnpm@10.12.1 --filter @gsc/web tours:export     # after changing floorplans.ts or tour.ts
& "C:\Program Files\Blender Foundation\Blender 4.2\blender.exe" -b --factory-startup -P assets/models/source/tours.py -- --seed assets/seed/project.json --out apps/web/public/tours
python assets/images/tour_sizes.py                        # 2048 px versions for phones
```

Or let the pipeline work out what's left: `bash assets/models/source/finish_renders.sh` audits every shipped render
(`python assets/images/tour_audit.py`: missing, half-written, draft-sized, blank, or older than its sources), renders
only those, refreshes the phone sizes and stale hero shots, then re-audits. It's safe to stop and re-run; stop it with
`taskkill //F //T //PID <winpid it prints>` so Blender goes down with it.

Options: `--quality draft` (2048 px, quick look), `--only studio,1br,lobby,...` (or `env`), `--stops living,bath`,
`--force-env` (re-render the cached window views after changing the exterior), `--test-orient` (marker test for
the panorama convention). A full final run takes about 3 hours on an RTX 3050 (window views ~3 min each, ~4–6 min
per stop). Conventions: plan (x, y) in metres with y towards the view → Blender (x, −y); every panorama is centred
on the view side; bearings are clockwise-from-above with +90° = plan +x (see `bearing()` in `tour.ts`).

## Contract with `packages/3d`

- Every unit is its own mesh named `Unit.meshId` (`<building>_F<floor>_U<pos>`, e.g. `T1_F12_U02`).
  The script asserts all 152 exist. The website matches meshes to seed units by that name for picking and tinting.
- Coordinates: 1 unit = 1 floor; podium 0–2; towers at x = ±8; unit quadrants at ±1.9; the sea faces −z
  (positions 01/02 are the sea side). `packages/3d/src/layout.ts` holds the same numbers. Change both together.
- PBR materials; plaster, bronze and stone carry 512 px textures with box-projected UVs at real-world scale.
  Static parts are merged per material, plus 152 unit meshes. `TowerModel` uses mesh geometry only (object
  transforms are ignored), so the script bakes every offset into the mesh data.
- If the GLB is missing or fails to load, `TowerScene` falls back to procedural boxes from the same layout.
